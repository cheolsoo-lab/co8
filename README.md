# BTC·ETH 비트겟 선물 시그널 · 리스크 도구

## 실행
```bash
pip install -r requirements.txt
streamlit run app.py            # PC 브라우저 + 같은 와이파이의 폰(http://PC-IP:8501)
python run_backtest.py 1825     # 5년 백테스트 (첫 실행 시 데이터 수집 약 4분, 이후 캐시)
```
**폰 상시 접속**: 폴더를 GitHub에 올리고 Streamlit Community Cloud에 배포 (main file = `app.py`). 클라우드는 재시작 시 파일이 지워지므로 일지는 CSV로 내려받아 보관.

## 구성
| 파일 | 역할 |
|---|---|
| `data.py` | 비트겟 캔들(5년 페이징)·펀딩·미결제약정·롱숏비율, CoinGecko 도미넌스 |
| `indicators.py` | EMA·RSI·ATR·ADX·MACD·볼린저·일목구름·OBV·CMF·캔들패턴·스윙피벗 (미래참조 없음) |
| `strategy.py` | 특징량 생성 + 셋업 A/B/C + 점수화 + 손절/목표 산출 |
| `backtest.py` | BTC+ETH 공유자본 복리 백테스트, 수수료·슬리피지·일일손실한도 |
| `context.py` | 라이브 오버레이(펀딩, 롱숏비율, USDT.D, 시총, ETH/BTC, 내 거시 의견) ±15점 |
| `risk.py` | 손절 기준 수량·레버리지 계산, 일일 손실/연패 잠금, 복리표 |
| `execution.py` | 비트겟 주문(기본 dry-run, 실주문은 키+`LIVE_TRADING=YES`+confirm 필요) |
| `app.py` | 대시보드 (시그널·차트·시장환경·백테스트·일지) |

## 전략
- **C. 4H 채널 돌파 추세추종 (기본 ON)**: 4H 상승/하락 추세 + 1D 정배열 + ADX≥20 상태에서 1H 종가가 4H 40봉 채널을 돌파. 손절 4H ATR×2.2, 3R에서 33% 익절 후 본절 이동, 4H ATR×4 트레일링.
- **A. 추세 눌림목 / B. 박스권 역추세 (기본 OFF)**: 5년 검증에서 기대값 음수/표본 부족.
- 점수: 1D 방향, 구름대, CMF·OBV·거래량, 반전 캔들, 지지저항 여유, 빗각(추세선), 4H MACD, 라이브 오버레이.
- 진입 위치 필터: 4H 레인지 상단 추격 금지(롱) / 하단 추격 금지(숏).

## 백테스트 결과 (2021-11 ~ 2026-11, 1H, 수수료·슬리피지 포함, 위험 1%/회)
- 기본 설정(C): 거래 241회, 승률 28%, 평균 +0.05R, 손익비 1.03, 5년 총 +4%, 최대낙폭 −27%.
- 파라미터 72개 격자 중 앞 60%·뒤 40% 모두 플러스인 조합은 43%뿐 → **견고한 우위(edge) 없음**.
- 수수료 0으로 가정해도 A/B는 음수 → 지표 조합만으로는 비용을 이기기 어렵다는 뜻.
- 일 1% 복리(연 37.8배)를 재현하는 설정은 찾지 못했습니다. 파생/거시 오버레이는 과거 데이터가 없어 미검증.

## 사용 원칙
1. 신호가 없으면 **관망**이 정상. 신호는 주 1회 안팎.
2. 실전은 최소 수량·수동 주문으로 시작, 일지로 실제 성과를 쌓은 뒤 판단.
3. 1회 위험 1%, 일 손실 3% 도달 시 중단, 3연패 시 쉬기.

## 방향 예측 검증 (direction.py)
`python direction.py` — 11개 방법(1D 추세·50일선, 4H 추세·구름대·RSI·MACD, 빗각 2종, 오더블록, 지지저항, 모멘텀)의 4H/24H/72H 상승·하락 적중률을 우연 수준과 비교(겹침 보정)하고, 워크포워드 로지스틱 확률모델을 표본외로 검증. 결과는 `state/dir_result.json`.
- 24H·72H: 거의 모든 방법과 확률모델이 50% 안팎(우연). 추세·모멘텀 계열은 오히려 50% 미만.
- 4H: 오더블록 약 53~55%, 확률모델 표본외 52.7%(확신도 높을수록 54~55%). 그러나 맞힌 방향의 평균 수익이 비용(약 0.16%)보다 훨씬 작아(+0.3bp) 단독 매매 근거는 아님.
- 펀딩비는 비트겟이 최근 약 90일만 제공해 5년 검증에서 제외.

## 차트 모양 분석 (patterns.py · shape_test.py)
와이코프식 매집/분배 박스, 스프링·업쓰러스트, OBV 괴리, 흡수 거래량, 이중바닥/천정, 헤드앤숄더, 삼각수렴을 4H 기준 규칙으로 구현(마감 후에만 사용).
- 확률모델에 모양 특징을 추가해도 표본외 정확도는 오르지 않음(4H 52.7→52.7%, 24H 52.8→52.1%, 72H 49.8→49.3%).
- 박스 이탈 방향의 '진짜/가짜 매집' 특징은 경계 거리 효과를 통제하면 유의하지 않음.
- 고전 패턴(이중바닥·헤드앤숄더·삼각)은 우연 수준 이하. 유일한 후보: 스프링+OBV괴리 → 24H 상승 54.7%, 평균 +0.29% (다중검정 미통과, 가설 수준).

## 시장 국면과 목표 (regime.py)
일봉 SMA20/50·기울기·ADX로 4국면(상승추세/하락추세/상승편향 횡보/하락편향 횡보)을 분류하고, 변동성(EWMA σ√h) 기준 7·14일 도달 구간을 표시. `python regime.py` → `state/regime_result.json`.
- 국면 방향이 n일 뒤 맞은 비율: 1~30일 모두 약 50% (p>0.2, 유의하지 않음).
- 국면 따라가기(일봉, 비용 0.08%): 샤프 0.54(횡보 관망)/0.73(횡보 편향 따라가기), 일 +0.07~0.11%, 최대낙폭 −58~61%. SMA50/200은 뒤 구간 −0.20로 불안정.
- 횡보의 끝: 직전 추세와 반대로 끝난 비율 약 70% (70건, 소표본). 하락추세 뒤 횡보 → 상방 76%, 상승추세 뒤 횡보 → 하방 69%.
- 도달 구간: 중앙값(50%)은 대체로 맞지만 먼 가격대(10%)는 검증구간 실제 도달률이 설계와 다름.

## 전환·횡보 패턴과 이벤트 (transitions.py · transition_test.py · combo.py · events.py · event_test.py)
4H 기준 규칙: 상승 후 하락전환(약세 다이버전스·업쓰러스트·고점 클라이맥스·구조붕괴 MSB↓), 하락 후 상승전환(강세 다이버전스·스프링·투매 클라이맥스·MSB↑), 박스 돌파/가짜돌파 복귀/상·하단 페이드. 결과: `state/transition_result.json`, `combo_result.json`, `event_result.json`, `shocks.csv`.
- 상승전환 쪽 일부(스프링, 박스 하단 페이드, 가짜 하향돌파 복귀)는 1~7일 뒤 방향 적중 58~65%이고 앞·뒤 구간 모두 50% 초과. 구조돌파(MSB↑) 확인 후 추종은 오히려 39~44%로 불리.
- 하락전환(숏) 신호는 믿을 만한 것이 없음(7일 기준 업쓰러스트 45%, MSB↓ 49%, 데드크로스 50%).
- 거래로 환산하면 기대값이 작음: 저점 반등 롱(손절3ATR·7일) +0.10R, t=1.2(유의하지 않음), 5년 +33%, 낙폭 −23%. 하락 편향 장에서는 −0.03R.
- FOMC: 발표 후 4시간 변동폭 평소의 2.4배(94%가 평소보다 큼), 방향은 예측 불가 → 위험관리(진입 보류·축소)용. 다음 FOMC는 앱에 표시.
- 급락·급등 쇼크 141건 중 FOMC 4건, 목록상 지정학·무역 등 9건, 나머지 약 91%는 원인 미분류 → 대부분 사전 예측 불가. 쇼크 후 3일 반등 62.5%(n=80)가 유일한 규칙.

## 새 관점 분석 (novel.py · novel2.py)
지표 없이 수익률의 구조만 본다: 기억력(분산비 VR), 질서도(순열 엔트로피), 내재시간(방향전환 DC), 적응 앙상블(Hedge), 순서 패턴 확률. 비용(편도 0.08%) 포함, 연 변동성 40% 타깃, 5년 BTC+ETH.
- VR·엔트로피·순서패턴·Hedge(η≥0.15): 회전이 잦아 비용에 져서 모두 음수(샤프 −0.7~−3.9). 순서패턴은 4H 방향 적중 53.6%/52.6%로 통계상 유의하지만 이익이 비용보다 작음.
- 내재시간(DC) 추종만 양수: 단일 5%·8% 샤프 0.43, 다중척도(3·5·8·12·16%) 0.38 (앞 0.64 / 뒤 0.01). 순서를 섞은 대조군 100회 중 3%만 이보다 좋음 → 약한 추세 기억은 존재. 역추세 방향은 전부 음수.
- 연 변동성 40%에서 연 +7%, 낙폭 −20%. 켈리 배율 = 샤프/변동성 ≈ 0.9배(추정오차 ±0.45 → 절반 이하 권장). 앱에 단계별 전환 가격 표시.

## 켈리·샤프를 내려놓은 관점 (goal.py)
- 샤프 대신 오메가·칼마·울서·CDaR·왜도로 재평가해도 1위는 내재시간(DC) 추종(다중척도: 오메가 1.03, 칼마 0.27, 낙폭 −18%, 왜도 +1.2). 나머지는 여전히 비용에 짐.
- 켈리 대신 '5년 내 목표 도달 확률'로 규칙 비교(경로 3000개): 엣지 추정 100%/50%/0% 세 세계. 대담 베팅(5배, 3배 도달 시 0.5배)이 3배 도달 확률 최대(43%/28%/17%)지만 반토막 이하 32~60%·낙폭 −50% 이상 79~88%. CPPI(바닥 70%)는 낙폭 −50%가 0%지만 상승 여력도 작음. 앱 검증 탭에 표.

## 자연·철학 관점의 코인별 독립 방법 (nature.py · nature_null.py · nature_live.py)
용수철(평형 복귀/이탈), 호흡(연속 봉 뒤), 일(거래량 대비 무결과), 리듬(요일·시간대), 흐름(상대 코인 선행), 균형(ETH/BTC 비율)을 BTC·ETH 각각의 데이터로 따로 훈련. 앞 60%에서 설정 선택(앞 샤프≥0.3인 관점만 동일비중 조립) → 뒤 40%에서 한 번 평가.
- BTC 조립(용수철·호흡·일·균형): 뒤 샤프 +0.34, ETH 조립(+흐름): 뒤 샤프 +0.80. 리듬은 비용에 져서 제외.
- 순서를 섞은 40회 대조: 평균 뒤 샤프 −0.38(BTC)/−0.29(ETH), 실제 이상이 나온 비율 12%/10% → 우연 가능성이 남은 약한 증거.
- 가장 일관된 단일 관점은 '호흡': 같은 방향 4H 봉이 BTC 4개/ETH 5개 이어지면 12봉(2일) 추종, 에피소드 310건/209건에서 55%/57% 지속, 앞·뒤 구간 모두 평균 양수.

## 5파냐 3파냐 판별법 (wave53.py · wave53_more.py · wave53_app.py · wave_live.fate53, 그림 state/wave53.png)
규칙대로 센 '5파 완성'(종가 지그재그, 차수 ATR×3·4·5·6·8, 코인베이스 BTC·ETH 11년 442번) 뒤 5파 끝을 먼저 넘으면(사실은 3파·연장) vs 4파 끝을 먼저 깨면.
- 기계적 몫: 방향 없는 무작위 걸음이면 P = 4파 끝까지 거리 ÷ (4파 끝까지 + 5파 끝까지). 시험 AUC 0.69 (실제 보정 logit P = 0.021 + 0.662·logit 거리비율).
- 그 위에 더한 단서(앞 절반 학습 → 뒤 절반·다른 코인 시험, 거울 우주 100개와 비교): 파동 비율 7개 · T5/T3 · 속도 · 5파 안 하위 파동 수 · RSI 다이버전스 · 거래량 · 채널 스로오버 · 상위 흐름 ·

## 웹에서 보기 (GitHub + Streamlit Community Cloud, 무료)
1. GitHub에 **비공개(Private)** 저장소를 만들고 이 폴더 파일을 올림 (data_cache 폴더는 올리지 않음 — .gitignore에 지정됨).
2. https://share.streamlit.io 에 GitHub 계정으로 로그인 → Create app → 저장소 선택, Main file = app.py → Deploy.
3. 비공개 저장소의 앱은 비공개로 만들어짐. 오른쪽 위 Share에서 내 이메일을 초대하면 휴대폰·회사 PC 어디서나 그 주소로 접속.
- 무료 계정은 비공개 앱 1개까지. 매매 일지(state/journal.csv)는 서버가 재시작되면 지워지므로 PC 실행 때만 신뢰.
- API 키는 필요 없음(공개 시세만 사용). 비트겟 접속이 막히면 OKX → 코인베이스 현물 순서로 자동 전환 (가격 차이 0.01~0.05%). 화면 맨 아래 '△ 접속 진단'에서 어느 서버가 되는지 확인.
- 안 돌아갈 때: Main file 경로(폴더 안이면 `btceth_web/app.py`), requirements.txt가 app.py 옆에 있는지, state 폴더가 올라갔는지 확인. 오류 내용은 'Manage app' → 로그.
